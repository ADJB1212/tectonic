## Existing replacements and remaining integration work

- convertStringToHexString() has already been replaced by faster-hex through append_hex_to_pool(); it is not a missing implementation.
- The other audited xetex-*.c modules have corresponding Rust function bodies. These still require ABI, shared-state, behavior, and call-path verification before replacing native compilation.
- The engine interface's setjmp/longjmp boundary still runs in C. The namespaced Rust attempt to call setjmp is not a validated replacement.
- Native globals and checkpoint serialization are still tied to xetex-ini.c. Translated namespaced globals are not a substitute for moving the live engine state.
- C++ TECkit and OpenType math implementations have translated Rust modules, but this inventory compares C function bodies; it does not certify C++ method parity or remove the project's external native library dependencies.
